# Work Plan: 이슈 #55 계정 삭제 안내와 세션 정리

## 작업

마이 화면의 계정 삭제 흐름에 삭제 범위·보관 예외·재가입 영향을 안내하고 정책·지원 공개 URL과
로컬 인증/푸시 정리를 연결한다.

## 배경

현재 확인 문구는 `정말 탈퇴하시겠어요?`뿐이며 정책·고객지원 URL, 삭제되는 데이터,
보관되는 정산 원장과 재가입 영향을 설명하지 않는다.

## 범위

- 개인정보처리방침, 이용약관, 커뮤니티 정책, 고객지원, 계정 삭제 공개 URL을 환경 설정으로 제공한다.
- 마이 화면에서 공개 URL을 외부 브라우저로 연다.
- 최종 확인 화면에 프로필/OAuth/알림 삭제, 정산 원장 익명 보관, 재가입 새 계정 처리를 안내한다.
- 중복 제출 방지와 처리 중·성공·실패 상태를 유지한다.
- 성공 뒤 현재 FCM token, Kakao/Apple 로컬 세션, secure storage를 정리한다.
- URL 실행, 삭제 서비스, 위젯 흐름 테스트를 추가한다.

## 제외 범위

- 공개 웹페이지 자체 구현은 togethertrip-web #6 범위다.
- 서버 데이터 삭제 정책과 notification 정리는 각각 main #125, notification #31 범위다.

## 설계

- 기본 공개 사이트는 `https://togethertrip.co.kr`이며 dart-define으로 재정의할 수 있다.
- 삭제 API 성공 이후 로컬 정리는 best effort로 모두 시도하고 마지막에 secure storage를 비운다.
- 정책 링크 실패는 사용자에게 오류를 표시하되 계정 삭제 상태에는 영향을 주지 않는다.

## 테스트 계획

- 정책 URL 생성과 실행 실패를 검증한다.
- 확인 다이얼로그의 정책 문구, 취소, 중복 탭 방지를 검증한다.
- 삭제 성공 뒤 push token 비활성화와 token storage 정리를 검증한다.
- `flutter analyze`, `flutter test`를 실행한다.

## 위험과 확인 사항

- 운영 배포 전 web #6의 각 URL이 비로그인 200을 반환해야 한다.
- 서버 삭제는 성공했지만 로컬 provider 정리가 실패할 수 있으므로 실패를 삼키되 로컬 토큰은 반드시 제거한다.

## 구현 상태

- 공개 정책·지원 URL dart-define과 외부 브라우저 실행을 구현했다.
- 삭제·익명 보관·재가입 영향을 안내하는 최종 확인 UI와 중복 제출 방지를 반영했다.
- 삭제 성공 후 FCM token 비활성화, Kakao/Apple 로컬 정리, secure storage 삭제를 best effort로 연결했다.
- `flutter analyze`, `flutter test` 전체 검증을 통과했다.
