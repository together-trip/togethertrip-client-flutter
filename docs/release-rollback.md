# TogetherTrip 앱 rollback 절차

모바일 스토어 배포는 이미 설치된 바이너리를 즉시 되돌릴 수 없으므로, 서버 호환성 유지·배포 중단·수정 버전 승격을 조합한다.

## 발동 기준

- 로그인/가입/자동 로그인 대규모 실패
- 다른 여행 데이터 노출, 인증 우회, 개인정보 유출 가능성
- 여행 생성·소비·정산 핵심 흐름의 데이터 손상
- 앱 시작 crash 또는 무한 로딩의 유의미한 증가
- 계정 삭제가 실패하면서 성공으로 표시되는 경우
- 푸시 딥링크가 권한 없는 화면을 노출하는 경우

## 즉시 조치

1. Play 단계적 출시와 App Store phased release를 즉시 중단한다.
2. 영향 버전, OS, 계정 유형, 최초 발생 시각과 재현 절차를 기록한다.
3. 서버가 이전 앱 계약을 계속 지원하는지 확인한다. 호환성 제거 배포가 원인이면 서버부터 이전 계약을 복구한다.
4. 보안·개인정보 사고 가능성이 있으면 토큰/키 폐기와 사고 대응 절차를 병행한다.
5. 스토어에서 문제가 있는 버전의 판매/배포 상태를 제한하고 지원 채널 공지를 준비한다.

## 수정 버전 배포

1. 문제가 발생한 release tag에서 hotfix 브랜치를 만든다.
2. 원인 재현 테스트를 먼저 추가하고 최소 변경으로 수정한다.
3. `version`의 build number를 반드시 증가시킨다.
4. [출시 체크리스트](./release-checklist.md)의 정적 검증, 핵심 E2E, 서명 artifact 검증을 다시 수행한다.
5. internal/TestFlight에서 재현 시나리오가 해결된 것을 확인한 뒤 단계적으로 승격한다.

## 플랫폼별 주의점

### Android

- Play Console에서 진행 중인 rollout을 halt한다.
- 이미 설치된 버전에는 더 높은 versionCode의 수정 AAB가 필요하다.
- Play App Signing key는 교체하지 않고 동일 upload key로 수정 버전을 서명한다.

### iOS

- phased release를 pause하고 해당 버전을 판매에서 제거할지 판단한다.
- 이미 설치된 앱은 회수되지 않으므로 서버 호환 또는 기능 차단이 필요하다.
- 더 높은 build number로 새 Archive를 올리고 expedited review 필요성을 판단한다.

## 복구 확인

- [ ] crash/error 지표가 정상 범위로 돌아왔다.
- [ ] 카카오·Apple 로그인, 여행/소비/정산, 탈퇴 E2E가 통과했다.
- [ ] 이전 앱 버전과 수정 버전 모두 서버 계약과 호환된다.
- [ ] 개인정보·인증 영향이 없거나 필요한 후속 조치를 완료했다.
- [ ] 원인, 대응 시각, 사용자 영향, 재발 방지 작업을 기록했다.
